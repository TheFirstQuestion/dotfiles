pr-data Script Design

Date: 2026-05-18  |  Status: Approved

Problem

update-pr-description Steps 1–2 require Claude to run 4+ separate gh commands, manually reason about stacked PR relationships, and locate the PR template — all re-derived on every run. This is deterministic data assembly that belongs in a script.

Solution

A bash script pr-data.sh that fetches all data needed by update-pr-description in one call: PR metadata, commits, resolved stacked PRs, PR template content, and the diff written to a temp file.

Interface

~/.claude/skills/update-pr-description/pr-data.sh [<pr-number-or-url>]
  • Argument optional — auto-detects current branch's PR if omitted (same pattern as pr-comments.sh)
  • On success: JSON object on stdout + diff written to temp file
  • On error: {"error": "..."} on stderr, exit non-zero

Output

stdout — JSON object

{
  "pr": {
    "number": 42,
    "url": "https://github.com/owner/repo/pull/42",
    "title": "Add rate limiting",
    "body": "## Summary\n...",
    "headRefName": "feat/rate-limiting",
    "baseRefName": "main",
    "author": "stevengopferman"
  },
  "commits": [
    "Fix typo in auth",
    "Add rate limiting middleware"
  ],
  "template": "## Summary\n\n## Ticket(s)\n\n## Testing\n",
  "stacked_prs": [
    {
      "number": 41,
      "url": "https://github.com/owner/repo/pull/41",
      "title": "Add auth middleware",
      "headRefName": "feat/auth",
      "baseRefName": "main",
      "relationship": "parent"
    }
  ],
  "diff_path": "/tmp/pr-data-owner-repo-42.diff"
}
  • template is the contents of the first PR template found, or null if none exists.
  • stacked_prs is [] when no stacked PRs are found.
  • diff_path is always present on success; the file always exists.

Diff temp file

Written to /tmp/pr-data-<repo-slug>-<number>.diff where repo slug is owner/repo with / replaced by - (e.g. pr-data-Dimer-Health-dimer-cura-node-42.diff).

Implementation Logic

PR Resolution

Identical to pr-comments.sh and extract-tickets.sh: parse optional arg for number and repo slug, fall back to gh pr view --json number for auto-detect, then gh repo view --json nameWithOwner for repo.

Parallel Fetches

Three fetches run in parallel using & + wait:

  1. gh pr view <number> -R <repo> --json number,url,title,body,headRefName,baseRefName,author,commits → PR metadata + commits
  2. gh pr list -R <repo> --json number,url,title,headRefName,baseRefName,body --state open → all open PRs for stacked detection
  3. gh pr diff <number> -R <repo> → written directly to the diff temp file

Template Detection

After fetches complete, check these paths in order — return the first match as a string, null if none found:

  1. .github/PULL_REQUEST_TEMPLATE.md
  2. .github/pull_request_template.md
  3. docs/pull_request_template.md

Stacked PR Resolution

For each open PR (excluding this PR itself), check these conditions in priority order — assign the first matching relationship label:

ConditionRelationship
other.baseRefName == this.headRefName"child"
other.headRefName == this.baseRefName"parent"
other.body or other.title contains #<number> or this PR's branch name"mentioned"

A PR matching multiple conditions gets the first matching label only.

commits Field

Extracted as [.commits[].messageHeadline] — flat string array, same shape as used by extract-tickets.sh.

Skill Integration

File: update-pr-description/SKILL.md — Steps 0 and 1 only

Replace the current Step 0 (manual gh pr view) and Step 1 (four parallel fetches) with:

Run ~/.claude/skills/update-pr-description/pr-data.sh [<number-or-url>]. Use the JSON output directly for all PR metadata, commits, template, and stacked PRs. Read the diff from diff_path.

Steps 2–7 are unchanged.
